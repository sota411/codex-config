# Geometry Nodes で調整できる構成を残す

反復配置、散布、寸法で変化するモデル、生成モーションで使う。単純な形状は通常のモディファイアで十分な場合もある。

## 生成するものと変更するものを分ける

最初に入力となる形状と、変更したい寸法・個数・密度・動きを決める。既存メッシュを加工するなら `Group Input` の Geometry を処理につなぐ。プリミティブから生成するグラフでは、その生成物を出力につなぐ。

幅や本数など、制作意図に対応する少数の入力を公開する。同じノードグループでも、各 Modifier は別の入力値を持てる。内部のすべての定数を操作項目にする必要はない。[公式の入力仕様](sources.md#official-geometry)

既存のノードグループやアセットが使える場合は、入力、単位、出力、外部依存を読んでから組み込む。複雑なグラフを毎回コードで書き直すより、既存の `.blend` から必要なグループを取り込む方が適する場合がある。[再利用の事例と仕様](sources.md#reuse)

## 実際のソケットと評価結果を確かめる

- ノードを作成したら、返されたオブジェクトと実際の `bl_idname`、入力・出力を基準に接続する。種類や動作モードでソケット構成が変わるノードでは、その設定後に読み直す。
- 同名のソケットがある場合は、方向、型、`identifier`、有効状態から対象を特定する。別の版の数値インデックスを流用しない。公開入力には `node_group.interface` を使い、Modifier 側の値も実際のソケット識別子で対応させる。
- Geometry が `Group Output` まで届くことを確認する。Field は要素ごとの計算であり、`Selection`、`Offset`、`Density` などの入力で評価されて初めて形状に影響する。
- Point、Face、Instance などの Domain が意図に合うかを確認する。トポロジー変更前の値を引き継ぎたい場合は `Capture Attribute` などを検討する。
- 変更した入力が読戻しで反映され、評価後の寸法・要素数・形状も変わることを確かめる。形状が変わらない場合は、未接続、消費されない Field、Domain、Modifier の表示状態を調べる。利用できる場合は Viewer と Spreadsheet で中間結果を確認する。

この方針は [公開スキルの実データ確認手順](sources.md#existing-skills) を参考にしている。ノードやソケットを推測で置き換えたり、失敗した代入を別の属性への代入で黙って補ったりしない。

Blender 5.2 では Modifier の入力が RNA に移行した。5.2.1 で確認した値の設定・読戻しは次の形になる。`socket` は実際の Interface 入力であり、グループを割り当てた `modifier` を使う。

```python
input_property = getattr(modifier.properties.inputs, socket.identifier)
input_property.value = value
assert input_property.value == value
```

浮動小数点を比較する場合は必要な精度で判定する。旧式の `modifier[identifier]` や `modifier.properties.inputs[identifier]` への代入を使わず、設定後の再評価でも結果を確認する。Compare と Random Value のソケット識別子にも 5.2 の変更がある。[5.2 の公式変更と実機確認](sources.md#python-cli)

## 反復物はインスタンスを維持する

同じ形状の配置には `Instance on Points` などを使う。`Realize Instances` は各複製の実ジオメトリが後続の加工や書き出しで必要になった場所に置く。大量の複製を実体化すると、メモリ使用量と処理負荷が増え得る。出力の手前に常に追加する「仕上げ処理」として扱わない。[公式の実体化仕様](sources.md#official-geometry)

計測もインスタンスに合わせる。元メッシュの頂点数だけでは、配置数や画面上の形状を検証できない。評価後のインスタンスを調べるか、計測用のコピーだけを実体化する。

## 乱数は Seed と安定した ID で管理する

`Random Value` の ID は `id` 属性を使い、なければ Index を使う。要素の順序が変われば、Seed が同じでも要素と乱数の対応が変わる。変更前後で対応を保つ必要がある場合は、行・列などから安定した ID を設計し、Seed とともに扱う。

`Distribute Points on Faces` の ID は、変形や密度変更後も残った点で維持される。同じ結果の再生成と、編集後も残った要素の対応を維持することは分けて確認する。異なる Blender の版まで同一結果になるとは仮定しない。[公式の ID・Seed 仕様](sources.md#official-geometry)

瓦のように整列するものは、格子を保ったまま形状の候補を切り替える方法もある。位置、角度、色を一律に乱す前に、参考資料のどこにばらつきがあるかを見る。[瓦の制作例](sources.md#x-observations)

## グラフと動きを人間が追えるようにする

役割ごとに Frame や Group を使い、入力、主要処理、出力を追える配置にする。説明は短い日本語で添え、Blender のノード型やソケットとの対応が分からなくなる命名を避ける。固定のノード数や配置間隔は要求しない。

時間だけで決まる揺れや繰り返しには、Scene Time や公開入力のアニメーションを検討する。フレーム内の反復には Repeat、前フレームの状態を使う処理には Simulation が候補になる。Simulation を使う場合は、途中のフレームへ直接移動した結果だけで正しいと判断せず、必要な順次評価やキャッシュを確認する。
