# Blender で編集可能な成果物を作る

ユーザーの意図を形状・材質・動きに落とし込み、Blender で結果を確認して渡す。作成したデータを後から調整できるように、必要なパラメータと構成を残す。

## 制作条件と既存データを確認する

- 実行ファイルと `blender --version`、利用できる操作経路を確認する。標準の CLI と `bpy` で作業を始められる。既に接続済みの MCP も利用できるが、スキルの利用に新規導入は必要ない。
- 依頼と既存ファイルから、対象、見た目の参考、寸法・単位、編集する範囲、静止画・動画・モデルなどの納品物を把握する。動画では尺と FPS、書き出しでは利用先も確認する。
- 既存作品では、対象のオブジェクト、コレクション、モディファイア、材質、ノードグループ、アニメーションを読む。新規シーンへの置換や全オブジェクトの削除で編集を代用しない。
- 元の `.blend` と生成コードの関係を確認する。スクリプトから作る新規作品は使用したコードを残す。手作業で編集された作品を、古い生成コードで上書きしない。

## 目的に合う表現を選ぶ

| 制作したいもの | 最初に検討する手段 |
| --- | --- |
| 単体の形状、対称形、一定の繰り返し | Mesh、Curve、Mirror、Array、Bevel などの標準機能 |
| 密度や個数で調整する散布、規則的な組み立て、生成モーション | Geometry Nodes。Python からグラフを構築し、主要な入力を公開する |
| シーンの組み立て、データの一括編集、保存・描画 | Blender Python API と CLI |
| 可動部、関節、ポーズ、演技 | Parent、Constraint、Keyframe、Armature。用途に合う標準機能を使う |
| 既にある形状・材質・ノード処理 | 既存データや Asset の再利用。編集可能なコピーには Append、元データとの連動には Link を検討する |

Geometry Nodes を使う場合は [プロシージャル制作](references/procedural.md) を読む。Python からメッシュを直接作るか、調整可能なノードグラフを作るかは、納品後に何を変更したいかで選ぶ。

## 小さく実行し、結果を見て修正する

1. 対象を明示できる処理は Data API を使う。必要な `bpy.ops` では選択・Active Object・Mode・Context を確認する。ノード型やソケット名、書き込み可能な属性を推測で決めず、実行版の API または既存データから確認する。
2. 大まかな形状・配置・比率を作り、必要な角度から確認する。参考画像がある場合は、同じ構図でも比較する。確認できた形状に材質と照明を加え、細部を仕上げる。
3. ひとまとまりの変更ごとに、対象データと軽いプレビューで結果を確かめる。毎回の全シーン再生成や、ノード数で決めた機械的な分割は避け、確認する範囲を変更に合わせる。
4. 見た目の問題は、形状、材質、照明、カメラのどこで起きているかを切り分ける。ログが成功していても、出力画像を開くまでは描画結果を確認済みにしない。

CLI の実行例、材質・照明、動画、保存・書き出しの注意点は [制作と検証](references/production.md) の該当節を読む。

## 再編集できる状態で渡す

- 依頼された納品物を作り、作業用の `.blend` を保存する。公開入力、必要なモディファイア、リグを残し、ベイクや適用は納品先で必要な範囲に限る。
- 保存したファイルを別の Blender プロセスで開き直し、変更した対象と必要な外部ファイルが読み込めることを確認する。生成処理を再実行する場合は、対象外を維持したまま不要な複製を増やさないことも確かめる。
- 静止画は実際の出力を、動画は代表フレームと動きを確認する。モデルの書き出しでは、利用先に必要な形状・寸法・材質・動きを確認する。
- ファイルの場所、後から変更できる項目、実行した確認、未確認の範囲を短く伝える。

根拠や対応版を調べるときは [調査出典](references/sources.md) を参照する。X の体験談を速度や品質の保証に置き換えない。
